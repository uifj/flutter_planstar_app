# ADR-0001: 组队支持与代抢在真实模式下调用后端未注册端点

- **状态**: PROPOSED
- **分类**: DEF
- **优先级**: P0
- **影响维度**: 生产功能 / 幻觉源
- **日期**: 2026-11-16
- **来源**: 全量接口审计（前端路由与实际调用面 × 后端注册路由表逐一比对）
- **修复 commit**: —

## 背景（Context）

前端 `ApiPaths` 声明并实际调用了 4 个后端不存在的端点：

- [api_paths.dart#L58](../../lib/app/network/api_paths.dart#L58) `v1/proxyBuyOrder/myOrders`
- [api_paths.dart#L61](../../lib/app/network/api_paths.dart#L61) `v1/pinTuanOrder/myOrders`
- [api_paths.dart#L62](../../lib/app/network/api_paths.dart#L62) `v1/pinTuanOrder/make`
- [api_paths.dart#L64](../../lib/app/network/api_paths.dart#L64) `v1/pinTuanCampaign/{id}`

后端注册表 [service.go#L71-L146](../../../planstar_kratos_server/planstar/internal/service/service.go#L71-L146) 中没有任何 `pinTuan` / `proxyBuy` 路由：

```text
rg -n 'pinTuan|proxyBuy' planstar_kratos_server/planstar/internal/service/service.go
# 无输出
```

真实模式（默认模式，未传 `--dart-define=PS_USE_DEMO=true`）的调用链：

- [group_buy_controller.dart#L13-L20](../../lib/features/group_buy/application/group_buy_controller.dart#L13-L20) 由 `DataSourcePolicy.pick` 选中 `RemoteGroupBuyRepository`
- [remote_group_buy_repository.dart#L16-L22](../../lib/features/group_buy/data/remote_group_buy_repository.dart#L16-L22) 委托 `GroupBuyApi`
- [group_buy_api.dart#L21-L58](../../lib/features/group_buy/data/group_buy_api.dart#L21-L58) 请求上述 3 个 `v1/pinTuan*` 路径
- [proxy_buy_controller.dart#L11-L17](../../lib/features/proxy_buy/application/proxy_buy_controller.dart#L11-L17) 选中 `RemoteProxyBuyRepository`
- [proxy_buy_api.dart#L23-L36](../../lib/features/proxy_buy/data/proxy_buy_api.dart#L23-L36) 请求 `v1/proxyBuyOrder/myOrders`

复现步骤：真实模式启动 App → 进入 `/group-buy`、`/group-buy/:id`、`/proxy-buy` → 请求 404 → 页面进入错误态并把 `'$error'` 原文直接渲染给用户（[group_buy_page.dart#L53-L57](../../lib/features/group_buy/ui/group_buy_page.dart#L53-L57)、[group_buy_detail_page.dart#L97-L103](../../lib/features/group_buy/ui/group_buy_detail_page.dart#L97-L103)、[proxy_buy_page.dart#L39-L43](../../lib/features/proxy_buy/ui/proxy_buy_page.dart#L39-L43)）。

附带语义不一致：[group_buy_api.dart#L20-L36](../../lib/features/group_buy/data/group_buy_api.dart#L20-L36) 的 `fetchCampaigns()` 名为"活动列表"，实际请求的是"我的订单" `myOrders`。后端即便补齐端点，也需先确认列表口径。

## 决策（Decision）

候选方案：

- **A. 后端补齐端点（长期正解）**：新增 `GET /v1/pinTuanCampaign`（活动列表）、`GET /v1/pinTuanCampaign/{id}`、`POST /v1/pinTuanOrder/make`、`GET /v1/pinTuanOrder/myOrders`、`GET /v1/proxyBuyOrder/myOrders`，并同步 `docs/api/API_CONTRACT.md`。**需后端排期与接口评审**。
- **B. 前端真实模式止血**：在 `isRemote` 下隐藏入口，或进入页面直接展示"组队/代抢暂未开放"空态，不再发出必然 404 的请求。
- **C. 增加前后端端点一致性测试**：以 `ApiPaths.all` 为前端调用面，断言后端 `Service.Routes()` 全覆盖，缺失即 CI 失败。

选定：**C 立即执行 + B 短期止血 + A 作为中期目标**。理由：P0 缺口会直接影响真机演示与线上可用性，但端点设计属于前后端共同决策；先把"前端声明 ≠ 后端注册"变成可拦截的自动化断言，避免同类问题再次静默上线，同时避免用户看到 404/原始错误字符串。

## 后果（Consequences）

- **正面**: 真实模式不再出现 404 错误页；端点一致性测试可拦截后续任何"前端先行、后端缺失"的回归。
- **负面/风险**: B 会使真实模式下组队/代抢入口不可用，需产品确认空态文案；A 完成前该功能仍只对 demo 模式可用。
- **中性**: `ApiPaths.all` 正式成为前端调用面的单一事实源，新增端点必须同时更新后端路由与契约测试。

## 验证（Verification）

```bash
# 1. 后端路由补齐断言（修复后应命中 5 条）
rg -n 'pinTuan|proxyBuy' planstar_kratos_server/planstar/internal/service/service.go

# 2. 前端路径清单自检
flutter test test/api_paths_test.dart

# 3. 前后端一致性（新增测试）
cd planstar_kratos_server/planstar && go test ./internal/service/ -run TestRoutesCoverClientApiPaths
```

- 真实模式抓包/容器日志：`route=/v1/pinTuanOrder/myOrders status=200`、`route=/v1/proxyBuyOrder/myOrders status=200`
- 手测：真实模式打开 `/group-buy`、`/group-buy/1`、`/proxy-buy`，不出现 404 或 `'$error'` 原文。
