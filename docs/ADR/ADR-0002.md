# ADR-0002: 搜索与热搜无后端端点，结果为已加载数据上的本地匹配

- **状态**: PROPOSED
- **分类**: DEF
- **优先级**: P1
- **影响维度**: 生产功能 / 幻觉源
- **日期**: 2026-11-16
- **来源**: 全量接口审计
- **修复 commit**: —

## 背景（Context）

搜索链路全部在前端完成，后端无对应端点：

1. **热搜写死**：[search_providers.dart#L137-L150](../../lib/features/search/application/search_providers.dart#L137-L150) 的 `hotKeywordsProvider` 返回 8 条编译期常量，注释自述"真实热搜来自 `v1/search/hot`"，但后端 [service.go#L71-L146](../../../planstar_kratos_server/planstar/internal/service/service.go#L71-L146) 无 `search` 路由，`ApiPaths` 中也没有任何 search 常量。
2. **结果本地匹配**：[search_providers.dart#L189-L228](../../lib/features/search/application/search_providers.dart#L189-L228) 的 `searchResultsProvider` 不对服务端发起请求，只在 `cityShowsProvider` 与 `feedControllerProvider` 已加载的数据上做 token AND 匹配（标题/创作者/场地/城市/分类/标签，含拼音）。
3. **覆盖范围有限**：真实模式下 [catalog_providers.dart#L274-L287](../../lib/features/catalog/application/catalog_providers.dart#L274-L287) 把 `cityShowsProvider` 直接指向 `showCatalogProvider`，而后者是分页控制器，每页 20 条（[catalog_providers.dart#L27](../../lib/features/catalog/application/catalog_providers.dart#L27)、[catalog_providers.dart#L47](../../lib/features/catalog/application/catalog_providers.dart#L47)）。即：用户未在首页/列表页触底加载时，搜索只覆盖服务端第一页 20 条企划。
4. **后端无关键词查询能力**：[service/project.go#L44-L47](../../../planstar_kratos_server/planstar/internal/service/project.go#L44-L47) 的 `GET /v1/projects` 仅接受 `categoryId` / `fundingStatus` / `sort` / `page` / `pageSize`，不接受 `keyword`，因此无法用现有列表接口模拟服务端搜索。

用户可见影响：热搜榜数字（32800 等）与可选词是编造的；搜索"命中数"只是本地缓存条数，不是全库结果；"综合/企划/动态"三个分域的角标数与真实数据量无关。

## 决策（Decision）

候选方案：

- **A. 后端新增 `GET /v1/search`（分域 + 分页）与 `GET /v1/search/hot`**：服务端做全量检索与热搜统计，前端改为 `AsyncNotifier` + 触底分页。**需后端协作**（DB 索引、分词/拼音策略）。
- **B. 过渡方案：复用 `GET /v1/projects` 增加 `keyword` 参数**：改动小，但只能搜企划、搜不了动态，且与"综合搜索"的交互预期不一致。
- **C. 短期止血：真实模式下热搜区隐藏或换成服务端可解释的入口（如分类/榜单），搜索页明确提示"当前仅搜索已加载内容"**。

选定：**C 立即执行 + A 作为目标方案**。理由：当前实现对外表现为"有搜索能力"，属于幻觉源；先用文案/入口收敛预期，避免把本地匹配结果当作全库结果；A 需要后端分词与索引设计，需单独排期。

## 后果（Consequences）

- **正面**: 用户不再被编造的热搜与不完整的命中数误导；搜索预期与实际能力一致。
- **负面/风险**: 真实模式下搜索能力弱化（仅已加载数据），需产品确认提示文案；A 未完成前无法支持"搜全库"。
- **中性**: `SearchResults` 模型与分域 tab 可原样保留，A 落地时只需替换数据源，页面结构不动。

## 验证（Verification）

```bash
# 后端无搜索路由（当前应无输出；A 落地后应命中 2 条）
rg -n 'v1/search' planstar_kratos_server/planstar/internal/service/service.go

# 前端 search 常量（当前应无输出）
rg -n "search" flutter_planstar_app/lib/app/network/api_paths.dart

# 回归
flutter test test/features/search
```

- A 落地后：真实模式搜索关键词（如"游戏"），抓包应出现 `GET /v1/search?...&page=1&pageSize=20 status=200`，且结果数随触底增加。
- 短期验收：真实模式进入搜索页，热搜区不再展示无来源的数字；搜索页在结果区给出"仅搜索已加载内容"的说明。
